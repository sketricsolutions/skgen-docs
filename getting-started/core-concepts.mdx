SketricGen combines product structure, agent configuration, runtime activity, and human control. These definitions describe how the current platform works.

## Teamspaces and Projects

A **Teamspace** contains members, roles, shared plan resources, and one or more Projects.

A **Project** scopes agents, conversations, connections, files, onboarding state, and collaboration. Always confirm the selected Project before creating or changing an agent.

## Adaptive Onboarding

[Adaptive Onboarding](/getting-started/adaptive-onboarding) is a saved Project conversation that recommends a useful first automation. It can use an optional public website, business goals, public research, and the live template catalog.

## Agent Space

[Agent Space](/ai-workforce/agent-space) is the live operational workplace for a Project. It shows agents, active work, schedules, collaborators, and human-input requests.

Agent Space does not define the internal agent graph.

## Agent Build

[Agent Build](/ai-workforce/agent-build) defines how one agent works. It contains the main agent, optional sub-agents, instructions, models, tools, skills, notes, and connections.

## Playground

[Playground](/ai-workforce/playground) is the Run tab inside Agent Build. It manages test conversations, live activity, human input, file attachments, workspace artifacts, and conversation history.

## Main Agents and Sub-Agents

The **main agent** receives the user's request, decides how to handle it, uses tools, delegates to sub-agents, and returns the final answer.

A **sub-agent** is a specialist called by the main agent. It does not talk directly to the user and cannot have its own sub-agents.

## Instructions and Models

**Instructions** define an agent's identity, responsibilities, process, boundaries, tool rules, escalation, and output expectations.

The **model** provides the underlying language and reasoning capability. Model selection affects capabilities, speed, cost, context, and supported media.

## Tools, Connectors, and Skills

A **tool** performs an action or retrieves information. Examples include File Search, Web Search, API Request, Structured Output, and custom MCP tools.

A **connector** is an approved connection to an external app and its actions. Access can be scoped to a Project and may use a managed connection or credentials supplied by your Teamspace.

A **skill** is reusable task guidance and supporting resources attached to an agent. Skills improve how an agent performs a type of work; they do not automatically grant access to an external app.

## Knowledge Bases

A [Knowledge Base](/shared-platform/knowledge-bases) stores approved website, document, text, or Q&A content that an agent can retrieve. Knowledge Bases help keep answers grounded in your information.

## Runs and Schedules

A **run** is one execution of an agent. It can contain model work, tools, sub-agents, files, messages, and human-input pauses.

A **schedule** starts repeatable work at a configured time. Test the agent manually before relying on scheduled execution.

## Files, Workspaces, and Artifacts

**Project files** can be available across agents in a Project. An **agent workspace** persists reusable files across conversations for one agent. A conversation or run can also have its own working files.

An **artifact** is a file or structured result created during work, such as a report, spreadsheet, document, image, or exported dataset.

## Human Input

An agent can pause a run and ask a permitted user for a choice, clarification, confirmation, or approval. Agent Space shows these runs under **Needs attention**.

Human input gives people control over uncertain or consequential steps. It is different from a public-channel handoff to a support representative.

## Traces

A **trace** records how a run progressed, including agent steps, tool calls, sub-agent calls, errors, latency, and credit usage. Use traces to explain an outcome and improve the Agent Build.

## Brand Agents

[Brand Agents](/brand-agents/overview) are customer-facing agents with website and brand context, Knowledge Bases, controlled tools, conversations, leads, and deployment settings. They are separate from the internal AI Workforce experience.
